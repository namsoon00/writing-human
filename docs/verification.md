## 2026-11-21 · 한 쪽에 원문 하나와 사진·글 함께 읽기

- 새 필사는 한 쪽에 원문 하나를 연결한다. 다른 원문이 연결된 쪽은 비어 있어도
  새 쪽을 열며, 글이 있는 자유 필기도 보존하고 새 쪽에서 시작한다. 같은 사본을
  다시 고르면 쪽·커서·입력·이어 쓰기 위치를 유지한다. 컨트롤러는 두 번째 원문으로
  기존 연결을 덮어쓰지 않는다. ‘필사하기’로 동작 이름을 통일했다.
- 새 쪽에는 원문 번호·개수와 여러 원문을 추가하는 조작을 표시하지 않는다.
  예전 다중 원문 쪽은 본문과 모든 사본을 보존하며 ‘필사 원문 → 이전 원문 기록’에서
  각 사본을 다시 읽을 수 있다. 기존 데이터를 자동으로 삭제하거나 분할하지 않는다.
- 원문 읽기와 쪽의 원문에서 사진과 글을 함께 표시한다. 휴대폰은 사진 위·글 아래,
  넓은 화면은 나란히 배치하며 사진의 비율과 지정 영역을 유지한다. 사진은 확대할 수 있다.
  필사 하단은 공간이 있을 때 작은 사진과 글을 함께 보여 주고, 작은 키보드 화면에서는
  온전한 글줄을 우선한다. 조합 중 사진 확대는 실행하지 않는다.
- 배포용 분리 작업본에서 `dart format`과 `flutter analyze --no-pub` 통과. `flutter test --no-pub` 전체
  208개 통과. 원문별 새 쪽·같은 원문 재선택·기존 본문 보존·추가 연결 거절·
  예전 사본 읽기와 사진/본문 배치를 검사했다. 실제 호스트 SQLite 파일 마이그레이션·
  재열기, 백업·동기화와 한글 composing·선택·스크롤 보존 회귀도 포함한다.
- `flutter test --no-pub tool/capture_single_source_test.dart` 통과. 번들 글꼴과
  직접 만든 검수 사진·문장으로 390×844, 900×700, 320×700의 글자 두 배,
  키보드 영역을 모의 적용한 필사 화면을 렌더했다. 이는 실기기 키보드 화면이 아니다.
- 로컬 release 웹의 Chrome에서 실제 버튼·입력과 합성 사진으로 휴대폰·넓은 화면의
  사진/글 읽기를 확인했다. 다른 원문을 선택하면 새 쪽이 열리고, 비어 있어도 이미
  원문이 있는 쪽은 유지됐으며, 같은 원문 재선택은 쪽을 늘리지 않았다. 기존 본문과
  각 쪽의 원문 사본이 보존됐고 런타임 예외가 없었다. 임시 프로필만 사용했다.
- [GitHub Pages 배포 44827822875](https://github.com/namsoon00/writing-human/actions/runs/44827822875)의
  `292932e`에서 포맷·정적 분석·전체 테스트·release 웹 빌드와 배포가 모두 통과했다.
  공개 주소를 새 Chrome 프로필에서 열어 390×844·900×700의 사진/글 읽기,
  다른 원문의 새 쪽, 원문이 있는 빈 쪽 보존, 같은 원문 재선택과 기존 본문 보존을
  다시 확인했다. 런타임 예외는 없었다. 직접 만든 검수 사진만 사용했고
  `output/single-source-20261121/*-browser.png`를 최종 배포 캡처로 교체했다.
- iOS/Android 실기기의 카메라·키보드·사진 확대 검수는 별도 범위다.

## 2026-11-21 · 첫 종이와 사진 구절 필사

- 첫 종이에 안내가 보이고 해당 위치를 누르면 바로 편집되는지 위젯에서 확인했다.
  한글 조합·선택 영역은 유지됐고 안내는 본문에 저장되지 않았다. 새 글에는 안내가 다시 나타나지 않았다.
- 사진에서 선택한 구절로 필사할 때 원본 사진과 선택한 글이 연결됐고, 기존 본문이 있으면 같은 글의 새 쪽이 열렸다.
  원문만 담기와 사진만 담기, SQLite 파일을 닫고 다시 열어 기록을 읽는 경로도 검사했다.
- 포맷 검사와 정적 분석을 통과했다. Flutter 전체 테스트 199건과 첫 줄 터치 회귀 테스트를 실행했다.
  로컬 미리보기의 모바일 크기 Chrome에서 합성 사진으로 필사 시작과 원문만 보관을 각각 확인했다.
- Android 디버그 APK와 iOS 시뮬레이터용 앱을 빌드했다.
- [GitHub Pages 배포 44824318714](https://github.com/namsoon00/writing-human/actions/runs/44824318714)가 완료됐다.
  배포된 주소에서 390×844 크기의 Chrome으로 사진 속 ‘책을’을 선택해 새 쪽에 연결했고 기존 본문이 남는 것을 확인했다.
  320×640에서는 ‘원문만 담기’가 필사 연결을 만들지 않았다. 두 경우 모두 브라우저에 저장된 원본 바이트가 시험 사진과 일치했다.
- 실제 첫 사용자 관찰은 참여자의 첫 터치와 발화가 도착하면 별도로 기록한다.
  iOS·Android 실기기 촬영과 실제 한글 키보드 입력은 이번 자동 검사 범위에 포함되지 않았다.

## 2026-11-21 · 읽고 고른 뒤 담는 원문 동선

- 첫 원문 진입에서도 목록과 ‘새 원문 찾기’·‘원문 담기’를 먼저 보여 준다.
  추천 시·시 목록·웹 검색의 제목은 같은 전문 미리보기를 연다. ‘전체 선택’과
  ‘이 구절 선택’은 등록 초안으로 가져오며, 저장은 마지막 ‘담기’에서만 한다.
- ‘담기’는 저장한 원문 읽기로, ‘담고 필사하기’는 필사 쪽으로 이어진다.
  글이 있는 쪽은 보존하고 같은 기록 끝의 새 쪽에서 시작한다. 담을 책을 바꾼
  경우에도 해당 원문을 펼치며 쓰던 쪽은 바꾸지 않는다. 사진·공유 경로도 같은
  완료 동작을 사용하고, 공유 전달 ID와 저장 뒤 확인 처리를 유지한다.
- 원문 등록은 실제 저장 콜백 성공 뒤에만 화면을 닫는다. 저장 실패 시 초안을
  고쳐 다시 담을 수 있고 중복 원문을 만들지 않는다. 입력·사진 인식 결과를
  수정한 상태에서 닫기와 뒤로 가기를 누르면 버릴지 확인한다.
- `dart format --output=none --set-exit-if-changed lib test tool/capture_preview_test.dart tool/capture_source_flow_test.dart`,
  `flutter analyze --no-pub` 통과. `flutter test --no-pub` 전체 198개 통과.
  첫 진입·전문 읽기·선택 전 미저장·두 완료 동작·다른 책에 담기·초안 닫기와
  저장 실패 재시도를 검사했다. 한글 composing·선택·스크롤 보존과 사진 인식,
  외부 공유 중복 방지 회귀, 실제 호스트 SQLite 파일 저장·재열기도 포함한다.
  메모리 저장 실패 테스트를 실제 디스크 장애 재현으로 간주하지 않는다.
- `tool/capture_source_flow_test.dart`로 합성 예문과 번들 글꼴을 렌더했다.
  390×844의 목록·검색·읽기·선택·저장과 320×700의 글자 두 배·닫기 확인을
  확인했다. 이 캡처는 실기기 화면이나 실제 작품 본문 검수가 아니다.

  확인했다. 새 원문 찾기 취소 후 목록 복귀, 담기 후 원문 읽기, 담고 필사하기 후
