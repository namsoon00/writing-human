# 구현 구조

## 브랜드 화면 구성

제품의 ‘브랜드 컨셉과 룩앤필’을 공통 위젯에 반영한다. PaperPanel은 현재 내지색에
섞은 미색과 종이 결을 쓰고 안전 영역을 포함한 바탕을 그린다. PaperPanelTitle은
잉크 표식과 쓰는 인간체 제목을 공유하며 PaperPanelHeader는 닫기와 가는 인쇄선을
배치한다. control_theme.dart는 버튼·목록·선택 상태와 가는 슬라이더를 같은 먹갈색으로
맞춘다. ToolsScreen은 작은 가운데 제목 아래 StationeryTool의 세워 둔 문구 그림으로
펜·형광펜·지우개를 고르고, 바로 아래에 두 줄 종이 견본을 둔다. 정적 벡터 그림의 실제 동작과
접근성 이름은 바깥의 버튼이 담당한다. 선택 도구에만 얇은 테두리를 그린다. 견본은 styleFor(book)의 내지·글꼴·크기·잉크를
읽으며 실제 본문과 같은 pencilTextSpan/passageWashStyle로 합성 구절을 밑칠한다.
견본을 만들거나 도구만 고르는 것으로 페이지·주석을 저장하지 않는다.
일반 세로 화면에서는 도구 선택·견본을 고정하고 설정만 별도 스크롤한다. 높이가
부족하거나 시스템 글자가 크면 전체 스크롤로 전환한다. 최대 글자 크기의 견본
줄 높이와 줄바꿈을 미리 반영해 슬라이더를 끄는 동안 조작부 위치를 유지한다.
FontSizeControl의 onPreviewChanged는 임시 크기만 전달한다. 드래그 중에는 견본만
갱신하고 기존 onChangeEnd에서 크기를 저장한다. 본문 입력 컨트롤러는 건드리지 않는다.

ToolsScreen이 현재 도구를 화면 상태로 보관하고 Workspace의 PaperTool을 함께 갱신한다.
선택 시 route를 닫지 않으며 닫기·뒤로 가기로 기존 편집기로 돌아온다. 펜에서는
글꼴 이름을 직접 누르고 크기 슬라이더를 사용한다. 형광펜에는 밑칠 색·농도를,
지우개에는 밑칠만 지운다는 안내를 표시한다.
상단 세 도구 중 현재 PaperTool 하나만 선택 표시하며 지우개를 다시 누르는 것으로
형광펜에 전환하지 않는다. 다른 도구는 상단에서 직접 고른다.
색·농도는 기존 BookDetailChoice의 tone/variant를 사용한다. 책 안에서는
saveBookAppearance로 pencil 항목만 변경하고 기존 내지·다른 override를 유지한다.
책 밖에서는 전역 WritingStyle의 pencil만 변경한다. 저장 실패와 재시도는 스크롤 밖에 둔다.
재질과 장식은 입력값·선택·composing 및 저장 구조에 관여하지 않는다.

## 로컬 필사 카페 · 1인칭 3D · 2026-11-22

`lib/cafe/cafe_camera.dart`는 미터 단위의 위치·yaw·pitch와 직교 카메라 축을
관리한다. 입구 눈높이는 1.62m, 앉은 눈높이는 1.18m다. `CafeWorld`는 바닥·벽·
천장·창틀·책상·의자·선반·책·잔·식물 등을 실제 3D 면으로 구성한다. `CafeRenderer`는
원근 투영, 눈 뒤의 면과 뒷면 제외, 근평면 클리핑, 레이어와 깊이 순서의 면 그리기,
방향성 조명·접촉 그림자와 텍스처를 Flutter Canvas에서 처리한다. 깊이 버퍼나
물리 기반 광선 추적 렌더러는 아니며, 겹치는 면은 정렬 방식의 한계가 있다.
사진 같은 완성도나 실기기 프레임 속도를 검증 없이 보장하지 않는다.

현재 Flutter 3.41.2와 Dart를 유지한다. 외부 3D 패키지, SDK 업그레이드,
별도 JavaScript 공간, 접속자 시뮬레이션은 추가하지 않았다. 네이티브와 웹이
같은 카메라·기하·표시 코드를 쓴다. 생성한 목재와 창밖 풍경은 앱 번들에 두며,
표지판은 쓰는 인간체로 한 번 그린다. 코덱·이미지·셰이더·Vertices·Ticker는
수명에 맞춰 해제한다. 이미지 로딩 도중 닫아도 늦은 결과를 기록에 쓰지 않는다.

`CafeViewController`는 입력과 무관한 카메라·자리·이동 요청을 관리한다.
방은 승인한 중간 규모 시안을 따라 8.8×10m, 천장 2.95m로 구성하고 중앙 테이블은
장축 3m·폭 1.15m의 6인 배치다. 창가 세 책상·안쪽 자리·추천 서가·개인 책장·
문구대·카운터를 같은 좌표계에 둔다. 움직이는 다른 방문자는 만들지 않는다.

드래그는 시선 회전이며, 바닥 클릭은 가장 가까운 실제 3D 면과 광선의 교차점으로
판정한다. 벽·책상 뒤의 대상을 관통해 고르지 않는다. 대상 면의 CafeTarget과 렌더
기하를 함께 사용한다. 의자와 가구 사각형에 22cm 여유를 둔 A* 경로를 구하고,
구간을 9cm 이하로 나눠 확인해 모서리 관통을 막는다. 책상 클릭은 접근점까지
걸은 뒤 앉는 전환을, 앉은 책상·노트 클릭은 기존 onWrite를 요청한다. 일어나면
현재 의자 옆으로 돌아간다. 이동 중 시선을 돌리면 경로와 도착 후 서가 동작을 취소한다.

이동할 때만 Ticker를 사용하고 동작 줄이기에서는 즉시 마지막 자세로 간다.
가만히 있는 동안 상시 렌더 루프는 없다. 비유한 포인터·카메라 값은 컨트롤러에서
거절하고 yaw를 정규화한다. 이 방어 처리를 모바일 빈 화면의 확인된 원인으로 보지 않는다.

`CafeScreen`은 하단 자리·쓰기 패널과 방향 버튼을 제거했다. 물체 근처의 작은
이름표는 물체와 함께 투영되고 실제 면 클릭과 같은 동작을 실행한다. 상단의 공간
안내는 키보드·스크린리더용 동등한 선택 경로다. 개인 책장을 누르면 책 선택 대화상자를,
추천 서가를 누르면 추천 이유와 공식 원문 링크를, 문구대를 누르면 기존 ToolsScreen을
연다. 책 구경만으로 기록을 만들지 않으며 쇼핑 기능은 없다.

재질·간판 아틀라스와 모든 3D 기하는 Flutter에서 표시한다. 생성 시안 자체를 배경으로
붙이거나 사진 같은 결과로 보장하지 않는다. 깊이 정렬·단순 조명 방식의 한계는 유지된다.
`CafeAmbience`는 직접 켠 합성 빗소리만 반복하고, 화면 종료·앱 비활성화 때 멈춘다.

책장의 `onCafe`는 기존 책장 경로가 닫힌 뒤 Workspace의 카페 경로를 연다.
Workspace는 `_cafeSeat`에 마지막으로 쓰기 시작한 자리만 보관한다. 닫기는 기존
방문을 유지하고 ‘카페 나가기’·컨트롤러 변경·계정 잠금은 방문 상태를 지운다.
JSON·SQLite·동기화·백업 스키마에는 카메라나 카페 상태를 추가하지 않는다.

입장·쓰기 시작은 소유 컨트롤러와 계정 잠금·조합 입력·저장 큐를 확인한다.
지금 펼친 쪽을 계속 쓰면 기존 PageEditor를 유지하고, 다른 책은 `_resumeBook`의
기존 쪽 이동 또는 초안 경로를 사용한다. 저장 성공 뒤에만 카페 경로를 닫는다.
실패하면 카페 화면을 유지하고 저장 재시도를 표시한다. 입력 리스너에서 본문·
선택·composing을 다시 설정하지 않는다. 카페의 책은 장식이며 사용자의 본문을 표시하지 않는다.

## 제품 용어와 저장 구조

[화면 용어](product.md#화면-용어)에 따라 화면의 ‘책 → 글 → 쪽’은 저장 모델의
`Book → WritingRecord → WritingPage`와 대응한다.

- `Book`은 책장에 보이는 제목, 표지와 내지, 장서표 소유자와 표지의 저자를
  가진다. `WritingRecord.bookId`는 글을 담고 있는 책을 가리키며 비어 있을 수
  있다. 다른 책으로 옮길 때 같은 글과 쪽의 ID를 사용한다. 연습장은 고정 ID의 책이다.
- `WritingRecord`는 내 글과 목차의 한 행이다. ‘새 글’은 별도 글의 첫 쪽을
  준비하고, ‘한 쪽 더’는 기존 `recordId`의 다음 쪽을 추가한다.
  `WritingPage.number`는 글 안의 번호다. 책 화면에서 보여 주는 쪽수는
  `Library.volumePages`의 책 순서에서 계산한다. `writtenOn`은 쪽을 처음
  저장한 날짜다.
- `RegisteredOriginal`은 `Book.originals` 또는 책 없이 담은
  `WritingRecord.originals`에 저장한다. 책의 원문 목록은 책과 그 안의 글에서
  볼 수 있는 원문을 조회한다. `citation`은 작품·쪽수·링크 등을 담는 출처
  문자열이다. 앱에서 담을 책의 ID와 별개다.
- `WritingPage.passages`에 원문 구간을 저장한다. `start`는 본문의 UTF-16 위치,
  `original`은 본문·사진·출처 사본이다. `attached`는 현재 방식의 경계,
  `following`은 끼운 자리 뒤에 이미 있던 글의 경계다. 입력값을 읽어 경계만 이동하며
  본문·선택·조합을 리스너에서 되쓰지 않는다. 빈 원문 경계는 자유롭게 쓰는 구간이다.
- `sourceOffset`과 `continued`는 기존 쪽의 원문 복원 호환을 위해 유지한다. 일반
  addPage는 원문 없는 빈 쪽을 만들며 비교·밑글씨·하단 원문은 현재 쪽의 연결만 사용한다.
- 이전 `guidedOriginalId`와 `originalSlip`은 읽을 때 구간으로 해석한다. 처음 구간을
  추가하거나 뺄 때 기존 연결을 함께 보존한다. SQLite의 기존 `passages` JSON 컬럼과
  웹·백업·동기화에 선택 필드를 추가하므로 DB 버전은 바꾸지 않는다. 연결 ID와 사본을
  병합하고 ‘빼기’는 빈 경계를 남겨 이전 원문이 다음 구간으로 번지지 않게 한다.
- 새 필사는 쪽당 원문 하나만 연결한다. `attachOriginal`은 추가 원문으로 기존 연결을
  덮어쓰지 않으며 같은 사본을 다시 고르면 저장하지 않고 현재 쪽을 유지한다.
  Workspace의 ‘필사하기’는 같은 원문 여부에 관계없이 저장된 쪽을 보존하고
  새 recordId의 첫 쪽을 saveDraft로 저장한다. 미저장 첫 초안은 같은 ID로 첫 필사 쪽을 저장한다.
  saveDraft의 title은 원문 제목으로 시작하고, 책 없는 원문 목록은 새 글에도 보존한다.
  ‘한 쪽 더’는 addPage로 같은 recordId의 원문 없는 빈 쪽을 추가한다.
  기존 쪽으로 돌아가는 동작은 onOpenWriting → _openPassage로 분리한다.
  원문 선택 콜백은 경로가 현재인지 확인해 닫히는 중의 연속 탭을 무시한다.
  이전 `passages` 배열은 삭제하거나 자동 분할하지 않는다. 원문 패널은 선택된 사본
  하나를 펼치고 여러 사본이 남은 예전 쪽만 별도 ‘이전 원문 기록’으로 접근한다.
- 원문 목록을 고치는 것은 이미 끼운 사본을 바꾸지 않는다. 원문 삭제는 연결을 비우고
  작성 본문과 출처 기록을 보존한다. 백업에는 구간 사본의 사진도 포함한다.

## 목차 제목과 직접 이름 변경 · 2026-11-22

`writing_title.dart`의 writingTitle을 목차·검색·내보내기가 함께 사용한다. 직접 지은 이름,
연결한 원문의 출처 첫 줄에서 가운데점 앞의 작품명, 처음 쓴 줄 순이며 비어 있으면
‘제목 없는 글’이다. 원문 목록 전체를 첫 원문처럼 쓰지 않고 실제 쪽에 연결한 사본을 읽는다.
자동 제목인 기존 ‘필사 N’ 값은 읽기에서만 대체하며 원래 기록을 자동 수정하지 않는다.
주소와 쪽수만 있는 출처는 제목에서 제외한다.

WritingRecord.copy는 title과 titleIsManual을 보존한다. 명시적 이름 변경은
setRecordTitle이 해당 기록의 제목·수동 표시만 바꾸고 기존 저장 큐를 사용한다.
JSON의 titleIsManual은 true일 때만 기록하고 이전 JSON은 false로 읽는다.
SQLite 14는 records.title_is_manual을 기본 0으로 추가한다. 이전 파일을 초기화하지 않고
기존 본문·원문·선택·쪽 ID를 보존한다. 백업·동기화 병합도 직접 지은 이름의 표시를 보존한다.
CollectionSheet의 하단 이어 쓰기는 평소 고정하고 낮은 화면·큰 글씨에서는 목록 끝에 둔다.

## 글자 크기

WritingStyle.fontSize는 기본 20, 범위 16–30으로 저장하고 SQLite 설정 JSON·웹·
백업·동기화에서 유지한다. 이전 저장값에 필드가 없으면 20을 사용한다. UI 텍스트의
기존 일괄 1.2배 확대를 제거하고 14 미만 라벨의 최소 크기와 OS 접근성 확대는
유지한다. 본문 크기는 편집기·줄 가이드·원문·인접 페이지 미리보기에 함께 적용한다.
두 손가락 제스처는 두 번째 손가락이 들어오기 전에 한 손가락이 이동하면 포기해
종이 넘김과 본문 스크롤을 유지한다. 크기를 미리 보여주고 제스처를 마칠 때
설정만 저장하며 한글 조합 중에는 크기를 변경하지 않는다.

## 글씨 쓰는 소리

`PageEditor`는 이전·현재 입력값의 편집 범위를 읽기 전용으로 비교한다.
완성형과 현대 자모를 기본 자모열로 풀어 새로 들어온 획만 요청한다.
예를 들어 ‘간’이 ‘가나’가 될 때 ㄴ은 이미 울렸으므로 ㅏ의 획만 추가한다.
웹 입력기가 조합 범위를 생략하면 커서 앞의 한글 한 글자에서 이어진 자모를 찾는다.
공백, 여러 글자 붙여넣기, 삭제, 같은 조합의 확정은 별도 요청을 만들지 않는다.

횟수와 순서는 자모의 펜 접촉 단위로 모델링한다. 사용자가 선택한 원음
`assets/audio/pencil-on-paper-original.wav`에서 짧은 획(3.307–3.404초),
보통 획(2.465–2.654초), 쓸어 긋는 획(5.656–5.861초),
꺾어 긋는 획(1.222–1.494초)을 추출했다. 원본의 속도·음높이를 유지하고
직류 성분, 8/17ms 양 끝 페이드, 0.84배 음량을 적용했다.
원본 출처와 해시는 같은 이름의 info JSON에 둔다. 키보드의 글자로 획의 모양을
추정하며 속도와 필압은 녹음에 담긴 움직임을 따르는 효과음이다.

획 사이에 24ms를 둔다. 새 입력 시 대기 중인 획의 길이 합이 450ms를 넘으면
울리는 획의 끝까지 기다린 뒤 최근 입력으로 넘어간다. 포커스 이탈·백그라운드 진입·
설정 해제 때는 예약을 취소한다. 웹은 신뢰된 포인터·터치·키 입력에서 Web Audio를
활성화한 뒤, 각 클립을 한 번 재생한다. 설치형은 미리 읽은 클립당 플레이어 풀을 사용한다.
넘김은 기존 음원, 105ms 간격과 최근 요청 정책을 사용한다. 초기 재생 요청은 240ms까지
유효하다. 효과음은 기본 꺼짐 설정과 기존 저장·동기화 필드를 사용한다.

## 낭독

`ReadAloudScreen`은 현재 본문과 `Library.volumePages` 순서의 본문을 읽기 전용으로
전달받는다. 쪽 번호는 그대로 표시하고 공백만 있는 쪽은 건너뛴다. 문단·연 사이에는
480ms, 쪽 사이에는 420ms 쉰다. 긴 문단은 문장 끝이나 공백에서 나누고
닫는 따옴표·문장부호·문단 내부 줄바꿈을 음성 엔진에 넘긴다.
정지, 닫기, 백그라운드 진입 시
진행 중인 낭독과 다음 구절까지의 대기를 취소한다.
선택한 여성 F1 하나를 사용한다. 음색 선택·저장·기기 TTS 경로는 제거하고 이전 설정은
읽지 않는다. 준비나 재생 실패 시 다른 음색으로 전환하지 않고 재시도를 안내한다.
설치형 앱은 ONNX Runtime으로 합성하고 `audioplayers`로 WAV를 재생한다.
iOS용 ONNX 플러그인은 iOS 16 이상을 요구한다. 웹은 ONNX Runtime Web과 Web Audio를 사용한다.

합성 속도 .90, 후처리 속도 .78, 음높이 -2반음으로 고정한다. MIT Signalsmith Stretch로
포먼트를 보존하며 속도와 음높이를 독립 처리한다. 설치형은 Dart 빌드 훅의 C++ 라이브러리를
isolate에서, 웹은 번들 WASM을 module worker에서 실행한다. 웹 모듈은 Flutter asset bundle에서
읽으며 worker와 blob URL은 정지·닫기 시 해제한다. 180Hz +1.2dB/3800Hz -2dB 선반 필터와
음량 제한을 적용하고, 마지막 유성 구간 약 1초를 .88 속도로 늘려 -3.5dB까지 부드럽게 줄인다.
자연스러운 문장 내 쉼은 유지하고 가장자리의 과도한 무음만 제한한다. 미리보기 제작의
Rubber Band는 앱에 포함하지 않는다. 두 처리 엔진의 파형이 동일하다고 간주하지 않는다.

F1 프리셋과 길이 예측 모델은 원본 Supertonic 3의 고정 리비전에서 가져온다.
새 다운로드에서는 나머지 세 모델에 가중치만 INT8로 줄인
[호환 모델](https://huggingface.co/askurios8/supertonic-3-int8)을 사용한다.
이전 캐시에 있는 정상 크기의 원본 파일도 사용할 수 있다. 설치형 앱과 웹은 새
파일을 SHA-256으로 검증해 캐시에 보관하고, 받은 바이트에 맞춰 진행률을 갱신한다.
캐시가 지워지면 다시 받는다. 필사 본문과 WAV는 기기에서 처리한다.
다음 문단 하나는 현재 문단이 재생되는 동안 합성하며, 정지하면 모델 다운로드를
취소하고 진행 중인 합성 단계가 끝난 뒤 모델 세션을 해제한다.

## 책별 꾸밈과 미리보기

`BookAppearance`에서 표지·내지·꾸밈을 고를 때마다
`LibraryController.saveBookAppearance`가 현재 책 메타데이터에 변경값을 합쳐
기존 순차 저장 큐에 넣는다. 저장 실패 시 메모리의 최신 설정으로 재시도한다.
쓰기 화면과 책장·목차·원문은 같은 책의 설정을 읽는다.
`Book.detailOverrides`에 없는 항목은 기존 `WritingStyle.bookDetails`에서 상속한다.
‘서재 기본값 사용’은 해당 요소의 책별 값만 키에서 제거한다. 편집할 때는 책 미리보기를
같은 화면에 두고 목록과 요소별 편집의 스크롤을 저장한다.
장식 편집에서는 탭과 편집 조작부의 실제 높이를 먼저 재고, 안전 영역과 저장 안내를 뺀 화면에서
남은 높이로 책 미리보기를 제한한다. 공간이 부족하면 한 스크롤 안에서 미리보기와 조작부를 표시한다.
SQLite v10은 `books.detail_overrides`에 빈 JSON 객체를 기본값으로 추가한다. 웹·백업·
동기화에는 선택 필드 `detailOverrides`를 사용한다. 동기화는 책별 꾸밈의 표시·모양·색·위치를
각각 병합하며, 처음 바꾼 요소는 공통 기준의 기본 설정과 비교한다.

## 책장과 이어 쓰기

`CollectionSheet`는 책장을 먼저 열고 책 상세와 ‘내 글’로 연결한다. `Bookshelf`는
기존 린넨 표지, 종이 결, 책별 표지 설정을 사용하고 화면 폭에 맞춰 선반을 그린다.
제목 검색은 현재 책 목록을 필터링한다. 찾기와 상세 열기는 기록을 저장하지 않는다.
‘내 글’의 `WritingSheetPreview`는 첫 본문과 날짜를 읽어 책의 내지와 현재 잉크·서체로
표시한다. 검색 결과는 본문에서 일치하는 위치를 사용한다.
‘연습장’은 고정 ID를 가진 일반 Book이다. 열 때 책 없는 기록의 bookId만 연결해
같은 저장 큐에서 저장하고, 성공하면 ‘내 글’과 같은 종이 미리보기 목록을 연다.
기존 기록·쪽 ID, 본문, 선택, 스크롤은 유지한다. 빈 연습장을 열어도 기록은 만들지 않는다.
보관함 안에서 책장과 기본 글 목록의 스크롤은 `PageStorage`에 각각 보관한다.
책장의 설정과 기록 관리는 책장 위에 별도 페이지로 올리고, 닫으면 기존 목록으로
돌아온다. 쓰기 도구의 글씨 설정과 책장 설정은 기존 `WritingStyle`을 갱신한다.
책장 설정은 종이 견본과 ‘기본 장식’에서 서재의 공통값을 갱신하며, 책별 선택은 `Book`에 저장한다.
기본 장식의 편집 화면은 목록 위에 올리고, 뒤로 돌아올 때 목록의 스크롤을 복원한다.
편집 화면은 바뀐 활성 요소만 현재 공통값에 합쳐 저장한다. 견본은 합성 문장과 선택값을 읽는다.
쪽 낭독은 활성 쪽을, 책 상세의 낭독은 해당 책을 넘겨 같은 낭독 화면을 연다.

표지에서 본문을 열 때는 기존 페이지 이동과 저장 큐를 사용한다. 앱을 열었을 때
저장된 활성 쪽이 그 책에 속하면 그 위치를 복원한다. 사용 중에는 책마다 마지막으로
연 쪽을 기억한다. 현재 실행에서 위치를 모르는 책은 가장 최근에 추가된 기록의
마지막 쪽을 연다. 내용이 없는 책은 글을 쓰는 시점에 저장하는 기존 작성 흐름을 사용한다.

휴지통의 쪽은 같은 ID와 기록, 번호, 본문과 주석을 유지한다. 활성 목록에서
분리하여 편집·검색·내보내기에서는 숨기고 전체 백업에 포함한다. SQLite는 같은
트랜잭션에서 휴지통과 활성 위치를 저장한다. 영구 삭제 후에는 동기화에 필요한 ID만 남긴다.

## 백업, 내보내기, 검색

`LibraryBackup`은 형식 식별자, 버전, 생성 시각과 라이브러리를 JSON에 담는다.
동기화 계정·기준 스냅샷과 기기별 마지막 내보내기 시각은 파일에 넣지 않는다.
가져올 때 구조와 참조를 확인한 뒤 현재 라이브러리에 추가한다. 내용이 일치하는
기존 항목을 재사용하고, 다른 내용이 같은 ID를 쓰면 책·기록·쪽의 참조를 새 ID로
연결한다. 같은 사본을 다시 가져오면 재사용한다. 새 스냅샷은 기존 순차 저장 큐로
저장하고 실패 시 다시 저장할 수 있다. SQLite는 한 트랜잭션으로 처리한다.
마지막 백업 내보내기 시각은 기기에만 저장한다. 웹에서는 브라우저에 다운로드를
요청한 시각이다. 파일 선택과 저장은 `file_picker`를 사용한다.

`writing_export.dart`는 필사 본문을 쪽 순서의 UTF-8 텍스트로, 책을 번들 한글
서체를 사용하는 A4 PDF로 만든다. `LibraryPassages`는 페이지 전체에서 문자열을
찾고 편집기와 같은 UTF-16 위치를 돌려준다. 결과 이동은 편집기의 스크롤만 조정한다.
책장·내 글·책 안 찾기와 원문 화면의 자동완성은 현재 목록의 저장 데이터에서
현재 단어의 접두어를 완성할 후보를 만들고 기기 안에서 필터링한다. 원문 검색은
본문과 출처를 검색하며 밑칠 필터와 함께 적용한다. 원문은 기존 JSON의 선택 필드
`registeredAt`에 등록 시각을 저장하며, 시각이 같은 항목과 이전 데이터는 기존 저장 순서를 사용한다.
터치 브라우저에서 검색칸의 입력 요소는 키보드·한글 조합·보조 기술의 입력을 받는다.
iOS에서 Flutter가 짧은 탭을 받으면 실제 글자 좌표에서 커서를 정한다. 한글 조합 중에는
선택을 변경하지 않는다. 본문용 터치 연결은 검색칸에 관여하지 않는다.


## 쓰기 위치와 새 잉크의 표현

`WritingPen`은 실제 삽입 위치의 커서 영역 중앙에 폭 1.2 논리 픽셀, 높이 72%의
세로획을 그린다. 현재 펜 색을 불투명도 50%로 사용한다. 삽입 위치·스크롤·포커스가
바뀌면 편집기 레이아웃이 끝난 같은 프레임에서 세로획을 그린다.
‘잉크 반응’은 새로 나타난 글자의 실제 편집기 페인트에만 150ms 동안 작은
불투명도 마스크를 적용한다. 글자를 겹쳐 그리거나 다시 배치하지 않는다.
한글 조합 중에는 효과를 적용하지 않고, 이미 보이던 글자도 다시 흐리게 하지
않는다. 사용자 설정과 OS 동작 줄이기를 따른다. 입력값과 저장 경로는 그대로 사용한다.

## 시·문장 자료 검색

한글 제목 검색은 띄어쓰기를 정규화해 위키문헌에 요청한다. 시집 하위 문서는
개별 작품 제목을 대조해, 전체 제목이 맞는 작품을 부분 일치보다 앞에 둔다.
작가 이름은 위키문헌의 저자 이름공간에서 검색한다.
‘웹 검색’에 입력한 검색어만 위키의 자동완성 요청에 포함한다. 조합이 끝난
검색어를 350ms 뒤에 보내고, 검색 모드나 입력값이 달라지면 이전 응답을 무시한다.
작품·작가는 앱의 판본 목록도 사용하고, 구절은 위키 검색 스니펫에서 현재
단어를 찾아 제안한다.
구절 검색은 위키문헌과 위키인용집에 일치 구절을 요청한다. 앱은 문서 제목과
ID로 출처 링크를 만든다. 미리보기는 공개 저작물 표시를 확인한 한국어 위키문헌의
판본을 페이지 ID와 판본 ID로 지정한다. 이 목록은 검색 전 탐색과 제목 일치 보완에
사용한다. ‘작품 둘러보기’의 소설은 고정한 동일 판본을 읽어 최대 여섯 개의 구절을
보여 준다. 알려진 장면은 본문 위치를 지정하고 나머지는 문단이나 문장 경계에서
본문 앞뒤의 여러 부분을 고른다. 사용자가 고른 구절과 판본·구절 출처, 새 필사 쪽을
한 저장본으로 커밋한다. 실패 시 선택한 구절에 머물며 기존 본문으로 재시도한다.
번역 소설 네 편은 Dao Consulting의 [CC BY 4.0 한국어판](https://lib.txid.uk/about/license)에서
작품별로 다섯 구절을 골라 번들에 둔다. 각 작품의 판본 주소·번역 출처·라이선스와
발췌 표시는 읽는 화면과 저장한 출처에 남긴다. 이미 저장한 전문에 대한 이전은 없다.
웹 검색의 ‘원문 가져오기’는 미리보기에서 전문과 출처를 등록 초안으로 전달한다.
긴 초안의 읽기 화면은 보이는 텍스트 구간부터 그린다. ‘글 고치기’에는 전문을 가진
기존 편집기를 쓴다. 커서와 선택만 달라질 때는 등록 화면 전체를 다시 만들지 않고,
본문이 같으면 정규화한 값과 특수문자 정리 여부를 다시 구하지 않는다.
웹 원문 화면과 검색 결과의 ‘캡처 가져오기’는 사진 선택기로 사용자가 고른
이미지를 등록 화면에 전달한다. 원문 확인에서 기존 사진 OCR을 사용한다.
검색 결과를 통해 작품의 주소를 알 때는 출처도 채운다. 작성 중인 초안을
바꾸는 경우 인식에 성공할 때까지 입력과 출처를 유지한다.
`SourceImportResult.startWriting`은 ‘필사하기’와 소설 외 내장 작품 선택 시 true다.
‘담기’는 저장한 원문을 펼치고, ‘필사하기’는 같은 책에 새 기록의 첫 쪽을 만들어 연결한다.
동일 원문을 쓰던 기록이나 저장된 빈 쪽도 재사용하지 않는다.
아직 저장되지 않은 첫 초안만 새 쪽으로 저장한다. 명시한 guidedOriginalId로 원문
전체를 sourceOffset 0부터 연결하며 원문 없는 빈 쪽을 추가하는 ‘한 쪽 더’와 구분한다.
작품 목록은 제목이나 작가 이름과 갈래로 기기 안에서 좁힌다. 판본 ID에 연결한 갈래,
첫 구절, 글자 수는 검색과 목록에서 사용한다. 갈래는 위키문헌의 작품 분류와 작가별
작품 목록을 확인한다. 글자 수는 공백을 포함해 같은 판본에서 읽은 본문으로 구하며
줄바꿈은 빼고 화면에서 반올림해 표시한다. 병렬 전사가 실린 경우에는
확인한 본문 블록을 명시한다. 작품을 열 때 Action API에서 고정 판본 ID와 해당 작품 또는
수록 시집의 공개 표시를 확인한 뒤 시의 글줄이나 산문의 문단을 가져온다. 작품 전체와
작품명·작가·판본 링크를 등록 초안에 전달한다. 다른 자료와 미리보기 실패 시 외부
원문 링크와 붙여넣기로 이어간다. 전문은 작품을 열 때 요청하며 등록 화면에서 저장한다.
원문·작가·네이버 링크는 iOS의 Safari 뷰와 Android의 Custom Tabs로 연다.
브라우저는 검색 화면 위에 Flutter 경로를 연다. 설치형은 시스템 웹 화면을 닫은 뒤
담기 버튼을 사용하고, 웹은 iframe 또는 새 탭에서 복사한 뒤 같은 버튼을 사용한다.
사용자가 버튼을 누를 때만 클립보드를 읽어 기존 등록 초안으로 전달한다. 작품 검색에서
연 문서에는 검색 결과의 출처를 함께 넣고, 작가 목록과 네이버는 기존 출처를 보존한다.
브라우저를 닫으면 검색 결과가 유지된다.

## 사진과 글을 함께 읽기

담은 원문 목록은 책 이름과 본문·출처 검색을 위에 두고 `OriginalListItem`의 색인표
표현을 사용한다. 책별 원문 쪽지와 구분 표시를 읽으며 원본 사진은 목록 표시 크기로
디코딩한다. 쪽지를 펼치고 돌아올 때 검색어와 목록 스크롤을 복원한다.

새 느낀 점 입력 진입점은 숨기고, 기존 reflection 모델·조회·수정·저장 큐와 한글 조합 보호는 유지한다.
기존 메모의 구절 위치와 본문 커서를 레이아웃을 바꾸는 과정에서 다시 설정하지 않는다.

원문 읽기 화면에서는 읽을 글을 먼저 표시하고 `_OriginalText.footer`에 출처와
`_SourceAttribution`의 작은 사진·필사한 쪽 링크를 둔다. 읽는 본문은 기존 글꼴·크기·잉크를
유지하며 줄 간격은 1.8이다. 주 필사 동작은 본문 스크롤 밖의 전체 너비 버튼에 둔다.
사진·출처·보조 링크는 같은 본문 스크롤에 포함해 긴 글과 큰 시스템 글씨에서도
읽을 수 있다. 사진의 `compact` 로딩 상태는 정적인 표식으로 본문 읽기를 방해하지 않는다.
‘원본 사진 보기’에는 원본 바이트를 표시하고 `InteractiveViewer`로 확대와 이동을 제공한다. 사진만 있는
원문은 `OriginalReadingLayout`으로 사진을 바로 보여 준다. 쪽의 원문 패널에서는
사진과 글을 함께 배치할 때 좁은 화면의
사진 높이를 읽기 영역의 30%(최대 210px)로 제한한다. 폭 500px 이상·높이 240px

## 원문 가져오기와 보관 · 2026-11-11

`RegisteredOriginal`은 ID, 본문, 선택 출처로 구성된다. `Book.originals`에
책의 원문을 저장하고, 책 없이 등록한 원문은 `WritingRecord.originals`에 둔다.
SQLite v9에서 두 테이블에 기본값이 빈 목록인 `originals` 컬럼을 추가한다.
원문 등록의 `saveNewOriginal`은 `_saveBeforePublishing`으로 저장한 뒤에만 목록에
반영한다. 등록 화면은 저장 콜백 성공 뒤에 닫히며 실패하면 초안과 사진을 유지한다.
같은 등록 화면의 재시도는 같은 원문 ID를 사용하고 공유 원문은 OS 전달 ID를 유지한다.
등록 취소는 변경 사항이 있을 때만 확인하며 본문·선택·composing을 리스너에서 되쓰지 않는다.
사진 또는 HTTP(S) 링크만으로도 원문을 등록할 수 있다. 사진의 선택 영역은
원본 크기에 대한 정규화된 좌표 `photoRegion`으로 보관하고 원본 바이트는 해시를
키로 저장한다. 미리보기에는 저장된 선택 영역을 적용하고, ‘원본 사진 보기’에서는
전체 사진을 연다. 영역을 고르는 화면은 원문 담기의 문자 인식 경로에 둔다.
iOS와 Android의 공유 보관함은 전달받은 사진을 전용 파일에 복사한다.
앱에서 원문 저장을 확인한 뒤에만 해당 공유 항목과 임시 사진을 지운다.

SQLite v12는 쪽에 `reference_only`와 `original_citations`를 추가한다. 글이 있는
쪽에서 새 원문을 고르면 비교 표시 없이 참고 원문을 보여 준다. 그때의 출처를
쪽에 남겨 원문 수정이나 삭제 이후에도 조회한다. 출처는 JSON·백업에 담고 동기화
병합에서 합친다.

SQLite v13은 쪽에 선택 필드 `original_slip`을 추가한다. 쪽지를 끼울 때 선택
범위의 글과 출처, 사진 ID·영역을 같은 쪽에 보관한다. 원문을 수정하거나
원문 목록에서 삭제한 뒤에도 끼울 때의 쪽지를 다시 볼 수 있다. 쪽지 교체와
제거는 본문이나 필사 가이드와 별도로 저장·병합된다. 백업은 쪽지만 참조하는
사진도 기기에 있으면 담는다.

라이브러리 JSON은 선택 필드를 사용하며 백업에서 복원한다. 동기화는 원문 ID를
기준으로 추가 항목을 합친다. 책에 묶은 기록의 원문은 책 범위에서 조회한다.

원문 수정은 저장된 원문 ID와 사진 파일을 유지한다. 기존 기록이나 쪽에 붙어 있던
원문은 목록에서 같은 항목으로 보이던 사본을 정리하고 정식 원문으로 옮긴다.
본문이 바뀌면 필사 범위를 편집 위치에 맞춰 옮기고 느낀 점은 보존한다. 수정된
구간과 겹치는 원문 밑칠·사진 줄 좌표는 해제한다. 원문 본문과 출처는 동기화에서
기존 값과 비교해 변경을 반영하며 이미 작성한 필사 본문은 수정하지 않는다.

`cleanOriginalText`는 원문 입력창에서 요청할 때만 호출한다. 글자·숫자·줄바꿈은
유지하면서 인용부호·말줄임표·대시·전각 문자와 자주 쓰는 기호를 키보드 문자로
바꾸고, 장식과 이모지는 그래핌 단위로 제거한다. 제거한 기호 양옆의 단어는
띄어 쓴다. `OriginalTextCleanup`는 원문 초안에 결과를 적용하고 입력이 추가로
바뀌기 전까지 원래 입력값과 선택 영역으로 되돌린다. 조합 중에는 정리와
되돌리기를 비활성화한다. 저장은 기존 원문 등록·수정 경로를 사용한다.

원문 삭제는 현재 책 또는 기록에서 해당 원문과 목록에 같은 항목으로 표시되던
사본을 제거한다. 삭제를 저장한 뒤 목록에 반영하며 실패하면 원문은 그대로 표시한다.
삭제한 ID는 소유 책·기록에 묶어 SQLite 설정 JSON, 웹 저장, 백업과 동기화에 남긴다.
같은 원문의 이전 저장본이나 기록·쪽에서 유래한 사본은 병합 뒤에도 다시 표시하지
않는다. 연결된 원문을 해제하고 필사 본문·선택·밑칠을 보존한다. 사진은 원문에서
연결을 제거하며 동일 사진을 사용하는 다른 원문은 계속 열 수 있다.

원문 메모는 `RegisteredOriginal.reflection`에 본문과 선택 밑줄(UTF-16 범위)을
저장한다. 기존 SQLite v9의 원문 JSON 컬럼에 선택 필드를 추가하며, 웹 저장·백업도
같은 JSON을 쓴다. 기존 기록이나 쪽에서 가져온 원문에 메모를 쓸 때는 원래
메타데이터를 보존하고 같은 범위의 원문 목록에 결정적인 ID로 저장한다. 같은 메모를
동시에 다르게 수정하면 동기화에서 두 내용을 문단으로 보존한다.

원문 패널 안의 편집기는 저장 버튼을 사용하며 조합 중에는 저장을 쉬고 실패하면
입력을 유지한다. 메모 서체는 Google Fonts의 Nanum Pen Script를 SIL OFL 문서와 함께
번들에 둔다. [원본 서체와 라이선스](https://github.com/google/fonts/tree/main/ofl/nanumpenscript)

원문 읽기 패널은 `PaperBackdrop`, `SourceSlip`, `RecordDivider`와 필사
밑칠 스타일을 재사용한다. 원문 화면에는 공통 미색 바탕과 옅은 결을 사용하고,
글꼴·펜·쪽지와 구분 표시는 책에 설정된 값을 사용한다.
쓰기 화면 하단 버튼은 현재 필사 중인 원문을 바로 펼치며, 연결된 원문이 없으면 목록을 연다.
같은 원문을 쓴 쪽이 여러 개면 현재 쪽의 위치를 우선해 ‘이어서 쓰기’로 돌아온다. 읽은 원문 ID는
현재 쪽과 책 또는 책 없는 기록별로 유지한다. 특정 원문을 여는 경로에서는
연결된 구절과 읽은 위치를 사용하며, 목록으로 돌아가면 보던 위치를 유지한다.
`NotebookReflection`은 RenderEditable의 글줄과 스크롤을 읽어 이미 저장한 메모를
그린다. 앵커 글줄이 온전히 보이고 빈 줄에 메모를 놓을 공간이 부족하면 줄 여백에
연필 표시를 둔다.
기존 메모의 수정 입력은 원문에만 있으며 한글 조합이 끝난 변경을 순차 저장한다. 저장에 실패하면
입력 내용을 유지하고 재시도한다. 메모의 텍스트를 지우면 reflection만 제거한다.

기존 `WritingRecord.source`, `sourceParagraph`, `WritingPage.passages`를 보존한다.
조회할 때 기존 기록 원문과 쪽의 원문·출처를 새 목록과 함께 표시하고, 같은 본문과
출처의 사본은 하나로 보여 준다. 이전 쪽의 UTF-16 구절 위치는 기존 편집 규칙을 따른다.

`originals.dart`는 쓰는 줄의 확정 문자열을 현재 범위에서 찾아 유일한 위치를 반환한다.
첫 단어 하나만 쓴 경우에는 원문 단어 양쪽 경계까지 일치해야 한다. 여러 단어를 쓰면
원문의 단어 시작에서 검색하고 마지막 단어는 입력 중인 접두어도 비교한다.
키보드가 닫혀 있고 필사 중이면 `TranscriptionGuidePainter`가 남은 원문을 본문
끝부터 옅게 그린다. 이때 필사 영역이 종이 하단까지 이어진다. 키보드가 열렸거나
참고용으로 열었으면 `TranscriptionReference`가 선택 범위를 하단에 배치한다.
커서 앞의 확정된 본문을 비교해 대응하는 글줄을 표시하고, 원문은 본문과
별도로 끝까지 스크롤한다. 텍스트 원문 칸은 표시 서체의 실제 줄 높이에
맞춰 최대 네 줄을 배치한다. 키보드가 열린 작은 종이에서는 필사 영역의
위 여백을 줄인다.
밑글씨는 입력값에 넣지 않으며, 조합 중인 마지막 음절의 자리는 비운다.
종이 스크롤 범위에는 남은 원문의 높이도 포함한다.
키보드가 열린 뒤 입력을 이어갈 때 공간이 충분하면 쓰는 줄을 중앙으로 옮긴다.
키보드와 원문 표시만 바뀔 때는 유효한 종이 스크롤 위치를 유지하고, 범위가
줄어들면 가장 가까운 위치에 머문다. 한글 조합 중에는 자동 이동을 보류한다.
편집기가 본문·선택·조합 값을 관리한다.

직접 고른 원문의 ID는 `WritingPage.guidedOriginalId`로 저장한다. SQLite v11에서
nullable 컬럼을 추가하고 웹·백업 JSON과 동기화에서도 선택 필드로 유지한다.
원문과 입력에서 공백·기호·문장부호를 제외한 그래핌을 순서대로 대조한다.
대응이 끊기면 마지막으로 맞은 위치에 머문다. 이어지는 위치에서 글자가
연달아 맞거나, 뒤쪽에서 충분히 구분되는 구절을 찾으면 진행을 재개한다.
그래핌의 원래 UTF-16 위치로 하단 원문과 밑글씨를 표시한다. 짧은 일치는
먼 곳으로 건너뛸 근거로 쓰지 않는다. 본문 끝 커서에서 밑글씨를 그리고, 본문
중간에서는 하단 원문을 저장된 커서까지의 필사와 이어받은 원문 오프셋으로 맞춘다.
삽입 내용을 커서 위치와 대조해 이미 있던 줄바꿈과 구분하고 원문 구간의
경계를 옮긴다.
연결된 원문과 보관본이 같은 경우, 전체 화면 읽기도 같은 계산 위치에서 시작한다.
일반 글의 원문 찾기와 메모 위치 계산은 문자열 일치 조건을 사용한다. 닫을 때는
편집기 포커스를 복원한다.

`lib/source/`의 사진·수신함을 원문 등록 화면에서 사용한다. 받은 글은 전용 수신함에
보관하고, 선택한 책의 원문이나 책 없는 새 기록이 저장된 뒤 해당 항목만 삭제한다.
수신 ID를 등록한 원문 또는 기록 ID에 연결해 재시도 때 중복을 막는다.

촬영·앨범 선택·공유·Android 선택 복구의 사진은 기본으로 전체를 바로 읽고, 읽는
순서대로 문단을 합쳐 한 입력칸에 표시한다. 직접 입력한 원문이 있으면 사진 읽기
동작에서 교체 여부를 확인한다. 사진 편집의 영역 선택은 선택 구역을 다시 읽고 글줄
좌표를 원본 기준으로 환산한다. 읽지 못했을 때는 원본 사진을 유지한다.
각 인식기는 문단·줄·단어와 정규화 좌표, 제공 가능한 신뢰도를 반환한다.
여러 단이 있는 페이지는 읽는 순서에 맞춰 문단을 합친다. 기본 인식은 긴 변을
2,400px까지 사용하며 사진 영역을 다시 읽을 때는 가능하면 원본에서 긴 변을
3,600px까지 읽은 뒤 자른다. 보정한 이미지에서 읽은 줄 좌표는 원본에 투영한다.
보정 전 결과로 돌아갈 수 있고 새 인식에 실패하면 현재 글을 유지한다.

‘원문 확인’은 인식 결과 전체를 보여 준다. ‘글 고치기’에서 Flutter 편집기의 범위
선택과 손잡이를 사용한다. 조합 중에는 범위 선택, 모드 전환과 저장을 기다린다.
사진 영역 선택은 원문 확인 화면에서 열리고, 취소하거나 다시 읽지 못하면 현재
글과 사진 영역을 보존한다. 저장은 확인한 전체 글과 원본 사진을
연결하며, 본문을 고친 경우 유일하게 일치하는 글줄의 원본 사진 좌표를 유지한다.
직접 지정한 사진 영역은 함께 저장한다. 사진은 OCR에 사용한 이미지와 별도로 원래
바이트를 SHA-256으로 참조하고 설치형 앱의 지원 디렉터리 또는 웹 IndexedDB에 보관한다.
사진만 보관한 원문에 글을 추가할 때는 원문 ID·사진·출처를 유지하며 저장 실패 시
편집 화면에서 재시도한다.

새로 시작하는 필사는 본문 전체를 쪽의 원문 사본으로 저장한다. 기존 `writingRange`는
저장·백업·동기화에서 읽고, 이전 쪽의 가이드와 연결은 원래 범위와 위치를 복원한다.
백업은 현재 기기의 사진을 포함하며 복원할 때 사진 해시를 확인한 뒤 기록을 합친다.

Android는 [ML Kit 한글 모델](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)을
앱에 포함한다. iOS 16 이상은 [Apple Vision](https://developer.apple.com/documentation/vision/recognizing-text-in-images)으로
책 사진을 읽는다. iOS 공유 확장과 앱은 [App Group](https://docs.flutter.dev/platform-integration/ios/app-extensions)을
통해 텍스트 수신함을 사용한다. 서명 배포 시 두 대상에
`group.com.writinghuman.writingHuman` 프로비저닝이 필요하다.

웹은 촬영본이나 이미지 파일을 브라우저의 [Tesseract.js](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)
작업자에서 한글 중심으로 인식한다. `tool/prepare_ocr.mjs`가 검증한 모델·엔진은
빌드와 함께 같은 출처에 둔다. 인식할 때만 받아오며 사진은 전송하지 않는다.
웹 인식에서 여러 줄이 같은 중앙 여백으로 나뉘면 좌우 단을 별도로 읽는다.
단 범위 밖의 제목과 쪽수는 전체 인식 결과에서 유지한다.
로컬 웹 실행은 `node tool/prepare_ocr.mjs` 후
`flutter run -d chrome --dart-define=WRITING_HUMAN_LOCAL_ONLY=true`를 사용한다.
GitHub Pages·Sites의 빌드 스크립트에는 준비 단계가 포함된다.

## 책의 물성과 독서 흔적

린넨 표지의 WebP는 천, 책등, 테두리를 담는다. 작은 표지와 큰 앞표지는 제목과
압화에 각각 다른 영역을 배정한다. 압화는 같은 선택값으로 그리고 어두운 천에서는
색의 밝기를 높인다. 현재 책의 책갈피, 날짜인의 간격, 제본 폭, 원문 목록의 구분 표시와
쪽수 문양은 각 화면의 크기에 맞춘다.

아홉 가지 독립 설정은 `data/book_detail_style.dart`의 BookDetailsStyle에 보관한다. 기존 ribbon/bookplate/sourceSlip/pencil/ornament/binding/dateStamp에 recordDivider/pressedFlower가 추가됐다. BookDetailChoice의 enabled·variant·tone과 압화에 사용하는 optional placement를 기존 SQLite settings JSON과 웹 라이브러리에 저장한다. 이전 데이터에 새 키가 없으면 기본값을 읽는다. 동기화는 요소별 필드를 따로 병합한다.

`ui/book_detail_design.dart`는 요소별 이름·세 모양·네 색을 정의하고, `ui/book_detail_tools.dart`는 개별 미리보기·표시 스위치·모양/색 칩·해당 요소만 초기화를 제공한다. 책장의 ‘설정 → 기본 장식’에서 연다. 장식 숨김은 메타데이터를 지우지 않으며 평문 책 정보·원문·날짜를 유지한다. `paper_palette.dart`와 `ink_mark.dart`를 분리하여 종이 면과 장식이 서로를 가져오는 의존 순환을 제거했다. 자세한 조형·상태·경계는 [독립 설계](book-details-design.md)를 따른다.

`ui/book_details.dart`의 천 책갈피·직조 헤드밴드는 정적인 CustomPainter다. 종이쪽지·장서표·날짜인·판면 장식은 실제 Flutter 위젯으로 표시한다. 장식 그림은 IgnorePointer/ExcludeSemantics로 입력과 분리하고, 날짜·이름·조작부는 텍스트와 접근성 이름을 유지한다. 장서표는 보관함의 책 안쪽 스크롤 목록에 배치해 작은 화면에서도 넘쳐나지 않는다.

Book.owner는 저자와 별개인 장서표 이름이다. WritingPage.writtenOn은 생성 시 기기 현지 날짜의 YYYY-MM-DD이며, 과거 페이지는 null을 유지한다. WritingPage.pencilMarks는 UTF-16 start/end 목록이다. Library JSON 버전 1의 optional 필드로 추가했다. SQLite v4는 books.owner, pages.written_on, pages.pencil_marks를 ALTER TABLE로 추가하고, 데이터·선택·스크롤을 보존한다. 종이·펜·글꼴 설정과 분리된 기록 메타데이터다.

`ui/pencil_marks.dart`의 PencilTextController는 저장된 범위의 글자 배경에 밑칠을 그리는 span을 생성한다. composing 밑줄은 별도로 표현하며, controller.value·selection·composing을 리스너에서 되쓰지 않는다. 구절 표시/부분 지우기는 LibraryController에서 저장하며 기존 편집기 키와 컨트롤러를 유지한다. 본문 수정은 공통 앞/뒤 문자열의 바깥에 남은 표시를 이동·분할하고, 바뀐 글자의 표시는 제거한다. emoji surrogate pair를 편집 경계에서 분리하지 않는다. 페이지 미리보기·넘김에도 같은 span 표현을 사용한다.

동기화에서는 장서표 이름을 책 제목/저자와 독립적으로 병합한다. 같은 본문 및 한쪽 본문 변경에서는 표시 범위를 대상 본문으로 이동한 뒤 3-way membership으로 병합하고, 본문 충돌 사본에도 날짜와 표시를 복사한다. 서버는 optional 이름·날짜·범위를 검증하며 이전 JSON도 허용한다. 책마다 마지막으로 펼친 쪽은 라이브러리의 선택 필드 `bookPositions`에 저장한다.
SQLite는 기존 `app_state.settings`에 담고 웹·백업은 라이브러리 JSON에 담는다.
이전 기록은 기존 활성 쪽부터 기억한다. 동기화는 책별로 위치를 병합하고,
백업을 합칠 때는 기존 위치를 유지하며 새로 들여온 책과 쪽의 ID를 연결한다.



Flutter 3.41.2 / Dart 3.11.0. iOS·Android는 sqflite, 웹 미리보기는 package:web의 localStorage. 하나의 Flutter 화면을 반응형으로 배치한다. 웹용 별도 HTML 모조 앱은 없다.

## 현재 작성 흐름

Workspace는 마지막 활성 페이지를 즉시 보여 주며, 기록이 없으면 저장하지 않은 WritingPage 초안을 표시한다. 탭/포커스/스크롤만으로는 저장하지 않는다. LibraryController.saveDraft가 첫 실제 입력 또는 원문 메모를 기존 초안과 같은 page/record ID로 저장한다. PageEditor의 키와 TextEditingController를 유지해 첫 한글 조합도 다시 설정하지 않는다. 오류 안내·원문 표시가 생겨도 writing-surface 키를 가진 Expanded를 유지한다.

책 안의 상단 ＋는 쪽 추가의 저장 경로를 사용한다. 빈 책의 초안은 첫 쪽으로만 저장한다.
책 밖에서 상단 ＋로 연 새 글은 첫 입력까지 메모리 초안이다. 앱을 닫으면 쓰지 않은 초안만 사라지고 마지막 저장 글은 유지한다. 기존 글을 이후 새 책으로 묶을 때는 addBook + bindRecord로 같은 기록을 묶으며 빈 기록을 추가 생성하지 않는다. 데이터 형식과 DB 스키마는 바꾸지 않았다.

collection_sheet.dart는 필요할 때 여는 글/책 보관함이다. tools_screen.dart는 종이·잉크·글꼴과 펜/줄 가이드를 한 시트에서 독립 선택한다. 원문·페이지·동기화도 보조 시트이며 기존 계정 보호·저장 실패/재시도·기존 기기 기록 가져오기를 유지한다. 작성 화면은 폭 760 이하의 한 면으로 적응하고, 마케팅 배경과 휴대폰 프레임은 사용하지 않는다. 아래 첨부 이미지 개편 기록은 이전 UI 구조다.

현재 종이 화면은 paper.dart의 PaperBackdrop이 최대 폭 760의 연속된 면지·왼쪽 음영을 담당한다. 면지 소재는 24% 강도의 정적인 RepaintBoundary이며 입력/접근성 트리에서 제외한다. PageEditor는 별도 종이 카드 없이 실제 TextField와 읽기 전용 펜 레이어를 올린다. WritingGuides는 실제 본문 패딩·행 높이·스크롤을 읽어 줄 가이드를 그린다. writing_chrome.dart의 WritingHeader/WritingFooter가 최소 조작부를 담당한다. 작성 화면 상단에는 현재 책 제목이나 앱 이름을 양옆 버튼과 같은 높이로 표시한다. 포커스·키보드·크기 변경은 레이아웃만 조정하며 controller·selection·composing을 되쓰지 않는다.
안전 영역을 뺀 키보드 인셋만큼 편집기 하단을 줄이고 하단 조작부를 위로 옮긴다.
키보드가 열린 동안 하단의 쓰기 도구 자리에 키보드 내리기 버튼을 표시한다. 키보드
인셋을 주지 않고 뷰포트를 줄이는 모바일 웹을 위해 본문 포커스도 사용한다. 버튼은
편집기 입력 영역에 두고, 조합이 끝난 뒤에만 본문 포커스를 해제한다.
본문 바깥 여백·제목과 키보드 버튼은 조합이 끝난 상태에서 입력 포커스를 해제한다.
본문 안의 마지막 글줄 아래를 누르면 RenderEditable의 글 끝 좌표로 커서를 놓고 키보드를 요청한다.
같은 곳을 다시 눌러도 입력을 유지하며, 조합 중인 값은 변경하지 않는다.
iOS 본문에서 짧은 탭은 RenderEditable의 좌표를 기준으로 삽입 위치를 찾는다.
터치 웹의 투명한 본문 입력은 포인터 대상에서 제외하고 포커스와 키보드
입력에 사용한다. 입력 요소의 호스트는 WebKit에서 위치가 밀리지 않도록 Flutter
뷰의 원점에 고정한다. 짧은 탭의 touchend에서 포커스를 요청한다. 브라우저가
포커스를 유지한 채 키보드를 닫았으면 같은 요소에 다시 요청한다. 후속 마우스
클릭은 취소할 수 있을 때 막아 입력 포커스를 유지한다. 터치 웹에서는 비어 있는
본문 입력 요소의 선택 변경이 본문 삭제로 전달되지 않게 한다. 실제 삭제는
브라우저의 입력 이벤트로 처리한다.
Workspace는 글쓰기·형광펜·지우개 선택을 화면 상태에 둔다. 형광펜과 지우개를
고른 동안 PageEditor의 본문은 읽기 전용이고, PaperHighlighter는 RenderEditable의
글자 상자와 grapheme 경계로 포인터가 지나간 범위를 계산한다. 빈 곳에서 시작한
세로 드래그는 기존 본문 스크롤을 사용한다. 드래그 중에는 미리보기를 그리고, 손을
떼면 LibraryController에서 기존 PencilMark에 범위를 합치거나 겹친 부분을 뺀다.
본문·선택·composing은 유지한다. 포인터가 취소되거나 본문이 바뀌거나 조합이
시작되면 임시 표시를 폐기한다.
선택 쪽지는 EditableText의 툴바 앵커에 배치한다. 복사·잘라내기·붙여넣기는 Flutter의
선택 동작을 사용한다.

- lib/data/model.dart: Book, WritingRecord(bookId nullable), WritingPage(recordId, number, text, selection, scroll), Library(activePageId, writing). 버전 1 JSON 및 참조 구조 검증.
- lib/data/library_controller.dart: 사용자 동작, 변경 스냅샷의 순차 저장, 저장 상태와 재시도. 저장 순서가 역전되지 않도록 Future 체인을 사용한다.
- lib/data/sqlite_store.dart: 네 개의 관계형 테이블, 외래 키, 현재 버전 7. 이전 버전 1~6의 파일을 자동 이전한다. 부모를 REPLACE로 삭제하지 않고 갱신한다. 각 스냅샷은 트랜잭션으로 저장한다.
- lib/data/web_store.dart: 버전 1 단일 키 writing-human.library.v1. 동기·원자적인 setItem을 호출하며 할당량/접근 오류는 UI까지 전달한다. 모바일의 SQLite와 저장 구현은 다르다.
- lib/main.dart: 저장소를 연 뒤 기존 기록을 읽는다. 실패하면 복구 화면을 표시하며 빈 라이브러리로 대체하지 않는다.
- lib/ui/workspace.dart: 책장, 책 생성, 편집. 본문 controller는 페이지마다 한 번 생성하고 입력 중 되쓰지 않는다. TextEditingValue를 관찰해서 조합 중 텍스트도 보관하되 IME composing 영역은 재실행 시 복원하지 않는다. 선택 영역은 UTF-16 offset이며 복원 시 범위를 제한한다.
- lib/ui/paper.dart: 공통 종이/잉크 팔레트, 면지 이미지와 얕은 왼쪽 음영, 잉크 표식, 줄 가이드와 보관함의 린넨 표지. 소재는 RepaintBoundary로 편집과 분리하며 포인터·접근성 트리에서 제외한다. 애니메이션은 없다. lib/ui/writing_chrome.dart는 상단/하단의 실제 조작부를 담당한다. 소재 경로와 프롬프트는 docs/visual-assets.md를 따른다.

## 글씨 가독성

`ui/typography.dart`의 ReadingTextScaler는 일반 최소 문구를 14px로 올린 후
OS TextScaler에 전달하며, 그 외 크기를 일괄 확대하지 않는다. 시스템의 비선형 확대를 선형 값으로 치환하지
않는다. 0 크기는 유지하며 설정 저장이나 편집 값 변경은 없다. 본문·줄 가이드·펜 위치는
같은 MediaQuery 척도로 실제 레이아웃을 읽는다. 작은 표지 썸네일은 중복 장식 텍스트를
비례 크기로 유지한다. 날짜 안내 행은 Wrap으로 바꿔 접근성 확대에서도 넘치지 않는다.

서체는 `source/reading-v007.json`의 6 디자인 단위 바깥 윤곽 확대로 실제 TTF를 재생성했다.
공통 자모 공유·advance·cmap·NFC/NFD 조판을 유지한다. 단순 가짜 굵기나 이미지 텍스트가 아니다.

## 개발 중 서체 연결

현재 0.009는 `source/reading-v009.json`의 범위로 완성 음절의 획 외곽 크기와 아래선을
보정한다. 공유 자모의 윤곽을 음절마다 하나의 affine 변환으로 배치하고, 문자 advance와
기존 cmap/GSUB/GPOS/줄 메트릭은 유지한다. 실제 입력 문자열·조합 상태·커서·글꼴 선택·
크기 설정에는 별도 마이그레이션을 적용하지 않는다. 대체 서체 체인도 그대로 사용한다.
`review_balance.py`가 이전 TTF와 전 글자 폭·조판/커닝/비한글 윤곽의 동일성을 비교하고
크기 편차 및 실제 14–42px 견본을 기록한다. 경계 수치 검사는 최종 광학 승인을 대신하지 않는다.

WritingHumanDevelopment family를 pubspec.yaml에 등록했다. 0.007부터 현대 한글 11,172자·자모·ASCII·문장부호를 담은 실제 TTF이며 반복 자모를 TrueType composite으로 공유한다. OpenType ccmp는 현대 초성+중성 및 받침을 완성형과 같은 윤곽으로 조합한다. 본문은 기존
TextField와 TextEditingController를 유지하고 TextStyle의 family/fallback만
바꾼다. 개발 TTF의 미지원 글자는 NanumMyeongjo → NanumGothic → 플랫폼
대체 글꼴로 표시한다. 문자열·선택 영역·composing을 나누거나 다시 설정하지 않는다.

WritingStyle.useDevelopmentTypeface는 기본 true다. 전체 TextTheme와 명시적 UI 제목도
WritingHumanDevelopment + NanumMyeongjo/NanumGothic 대체 체인을 사용한다.
기존 설정은 typefaceDefaultsVersion이 없으면 쓰는 인간체로 한 번 전환한다.
새 저장에는 typefaceDefaultsVersion: 1을 기록해 이후 명시적으로 선택한 다른 본문
글꼴도 저장·복원한다. 본문·선택·스크롤·종이·잉크와 fontIndex 0–2, DB 버전은 유지한다.
동기화 병합에서는 fontIndex와 개발 서체 여부를 한 선택으로 처리하며 종이·펜과
독립적으로 합친다. 서버는 optional bool의 타입을 검증한다. 기존 서버도 style의
추가 필드를 보존하므로 인증이나 요청 구조 변경은 없다.

일반 주소·빈 종이·기존 페이지·보관함·도구·대화상자에 쓰는 인간체를 기본 적용한다.
이전 데모 주소도 같은 실제 기록·기본 글꼴로 열린다.

## 저장과 복원

본문, 선택 영역, 본문의 스크롤 변경마다 저장 요청을 큐에 넣는다. 마지막 열린 페이지와 책장/편집 화면 여부도 저장한다. 스크롤은 편집기의 첫 레이아웃에서 유효 범위로 보정한 뒤 그린다. 마지막 위치는 자동 스크롤이나 포커스로 덮어쓰지 않는다. 페이지에 키보드를 자동 표시하지 않아 복원 직후 글을 읽을 수 있다.

모바일 경로: getDatabasesPath()/writing-human-v1.db. 웹 캐시는 origin·계정별로 분리된다. localhost와 배포 URL은 서버와 캐시를 공유하지 않는다. 배포 웹의 기록은 로그인한 같은 계정의 D1 스냅샷과 동기화하며 상세 정책은 docs/sync.md를 따른다. 웹 동시 수정은 서버 버전 확인과 충돌 보관 필사로 처리한다. 파일 백업은 기록 관리 메뉴에서 제공한다.

매 변경 시 전체 라이브러리 스냅샷을 저장하는 구현이므로 장편·대량 기록 성능은 아직 검증하지 않았다. 다음 저장 최적화에서는 변경된 페이지의 갱신으로 전환하되 저장 순서, 실패 표시, 페이지/커서 복원 보장을 유지해야 한다. 종료 직전 OS의 강제 프로세스 종료까지 저장을 보장한다고 주장하지 않는다. 저장 완료 표시 후 종료하는 흐름을 검증한다.

호스트의 실제 SQLite 파일 테스트를 위해서만 sqflite_common_ffi를 개발 의존성으로 사용한다. 해당 sqlite3 패키지의 문서에 따른 hooks.user_defines.sqlite3.source: system을 지정했다. 테스트용 네이티브 바이너리 다운로드의 무결성 오류를 우회하거나 검증을 끄지 않고 OS SQLite를 사용한다. 모바일의 실제 저장소는 sqflite다.

## 첨부 이미지에 맞춘 UI 개편

책장은 큰 카드 대신 세로 목록으로, 책 상세는 표지·진행선·목차/필사 기록/책 정보로 구성했다. 편집 화면은 접힌 원문 메모, 종이 페이지, Aa·펜·페이지·키보드 도구 막대를 사용한다. 모바일은 전체 화면이고 넓은 웹 화면에서는 같은 앱을 중앙의 좁은 프레임 안에 표시한다.

WritingStyle은 종이, 펜, 글꼴, 줄 가이드, 즐겨찾기를 독립적으로 보관한다. Library JSON 버전 1의 optional style 필드로 추가했으며 이전 웹 데이터는 기본값으로 읽는다. SQLite 스키마는 버전 2다. app_state.settings와 records.source 컬럼을 ALTER TABLE로 추가하고 기존 테이블·본문·마지막 위치는 삭제하지 않는다. 기록에 source 원문 메모가 추가됐다.

도구 화면은 기존 편집기 위에 표시한다. 선택 변경으로 TextEditingController를 새로 만들거나 본문/selection/composing을 덮어쓰지 않는다. 펜 선택은 잉크빛에 반영되며 종이·글꼴을 바꾸지 않는다.

## 입력 위치를 표시하는 세로획

lib/ui/writing_pen.dart는 TextEditingController·FocusNode·ScrollController를 읽기만 하는 장식 위젯이다. 한 프레임에 하나로 합친 post-frame callback에서 실제 RenderEditable의 getLocalRectForCaret를 읽고, global/local 좌표 변환으로 FittedBox·본문 패딩·스크롤·글자 크기를 반영한다. 텍스트 길이로 펜 위치를 추측하지 않는다.

입력과 스크롤에 맞춰 세로획의 위치를 갱신한다. 한글 조합 중에는 위치를 표시하고, 선택 영역이 펼쳐지거나 포커스를 잃으면 세로획을 숨긴다. OS 동작 줄이기를 켜면 확정 글자의 농도 효과를 쉰다.

펜 레이어는 IgnorePointer·ExcludeSemantics·RepaintBoundary로 입력과 분리한다. 새 TextEditingController를 만들거나 TextEditingValue·selection·composing·focus·scroll을 되쓰지 않는다. WritingStyle.penMotion은 기본 true인 optional JSON 값으로 기존 SQLite settings 및 웹 저장/동기화에 보관하며 DB 스키마를 바꾸지 않는다. sync/merge.dart에서 다른 도구 값과 독립적으로 병합한다.

DemoStore와 합성 문장은 개발 검증용으로만 남는다. 일반 앱에 예시 진입점이나 합성 기록 자동 생성은 없다.

## 동기화 추가

lib/sync/의 조건부 팩토리는 웹의 계정 세션과 계정별 localStorage를 연결한다. SyncCoordinator가 로컬 저장 후 원격 버전 확인·병합·재시도를 수행한다. server/index.mjs는 Sites 사용자 식별과 D1의 조건부 갱신을 사용한다. 서버 서비스 자격 증명을 클라이언트에 포함하지 않는다. SQLite 스키마는 sync_state를 추가한 버전 3이다. docs/sync.md에 병합·계정 변경·마지막 위치·IME 규칙과 설치형 앱의 현재 한계를 기록했다.

GitHub Pages 등 정적 호스팅은 `WRITING_HUMAN_LOCAL_ONLY=true` 빌드에서 세션·동기화 클라이언트 생성 전에 WebLibraryStore만 반환한다. 기본 빌드는 기존 계정 동기화를 유지한다. Pages 산출물은 build/github-pages로 분리하며 Sites Worker·D1 배포와 섞지 않는다. docs/github-pages.md에 실행·배포 절차와 현재 접근 권한 한계를 기록한다.

## 페이지 전환 · 2026-11-10

PageTurnView는 Scaffold 본문 전체를 감싸 상단 브랜드·본문·하단 도구를
한 장으로 넘긴다. 실제 PageEditor는 하나다. 떠나는 화면의 마지막 paint layer만
메모리 이미지로 읽어 360ms 곡선 클립·종이 뒷면·그림자를 덧댄다. 장식은
IgnorePointer/ExcludeSemantics이며 이전 편집기의 포커스·저장 리스너를 복제하지 않는다.
같은 page ID의 첫 저장·도구 변경에는 전환하지 않는다. 새 쪽 입력은 연출을
즉시 끝낸다. OS disableAnimations, 비활성 TickerMode, 20,000자 초과 본문은
연출을 생략해 입력과 기록을 우선한다. 스냅샷은 최대 배율 2·약 200만 픽셀로
제한하며 PNG 인코딩·디스크 저장·업로드를 하지 않는다. 전환 완료·입력·빠른 역방향
전환·키보드/화면 크기 변경·dispose 때 이미지를 해제한다. 화면 캡처가 불가능하면
이동은 즉시 완료한다. 컨트롤러가 바뀌면 이전 계정의 장식을 재사용하지 않는다.

Workspace는 조합 입력·계정 잠금·중복 이동을 검사하고 현재 저장 큐가 끝난 뒤
이동한다. 실패하면 현재 쪽에 머문다. 직접 쪽을 고르면 패널 뒤에서 목적지
편집기를 먼저 준비한 뒤 패널을 닫는다. 직접 이동에서는 직전 쪽의 스냅샷을
표시하지 않는다. PagesSheet에는 본문 일부를 담은 읽기 전용 미리보기가 나온다. 입력 리스너가 본문·selection·composing을
다시 설정하지 않는다. 명시적인 빈 페이지 추가에만 saveDraft(keepBlank: true)를
사용하며 기존 JSON/SQLite 구조와 도구 설정을 유지한다.

## 쪽수와 종이 스와이프 · 2026-11-10

WritingFooter는 64px 기본 높이 한 줄로 도구·쪽수·더 보기/완료를 배치하고
쪽수 아래 작은 저장 상태를 유지한다. 이전/다음/추가 버튼은 없다. 현재 번호를
누르면 PagesSheet가 열리고, 접근성 레이블은 현재/전체 쪽수와 증감 동작을 제공한다.

PaperSwipe는 수평 드래그로 한 번에 한 쪽만 넘긴다. 마지막 쪽의 다음 동작은
기존 _appendPage와 실제 저장 큐를 사용한다. 64px 이동 또는 36px 이상/500px/s
flick에만 반응하고 강한 역방향 마무리는 취소한다. 본문과 스크롤을 재배치하지 않는다.

읽기 상태의 종이는 수평 recognizer를 본문의 pan recognizer보다 먼저 등록해
가로 넘김을 구분한다. 탭과 세로 스크롤은 편집기, 길게 누른 뒤 움직이기는

실제 회전 다각형을 비교하므로 AABB만 겹치는 정상 배치를 막지 않는다. 벽·카운터 같은
고정 장애물, 문 앞 여유·경계·목적지 경로 검사는 유지한다. 식재의 이동은 정원의 둑
영역으로 제한한다. 정원은 같은 linkedWorld를 계속 쓰므로 실내에서 보는 나무와 꽃도 같다.

각 맵 최대 256개를 검사한다. v1에 없던 네 맵만 빈 맵으로 이행하고 기존 필수 필드가

## 직접 요청한 미디어 재생 세션 · 2026-11-25

userAudioIOS()는 playback + mixWithOthers를 사용한다. 카페·필기·쪽 넘김·낭독에서
이 컨텍스트를 사용하며 Android 경로와 입력 타이밍은 바꾸지 않는다. 웹 UserAudioSession은
navigator.audioSession을 feature detection하고 실제 소리 요청 또는 낭독 준비 시
type=playback을 요청한다. 자원을 만들지 않는 배경 silent output에는 연결하지 않는다.
API가 없거나 쓰기가 거절되면 기존 경로를 유지한다. 무음 파일을 따로 재생하거나
새 반복음·자동 재생·마이크 권한을 추가하지 않는다.

페이지 전역 AudioSessionLeases는 소비자별로 등록하고 마지막 소리가 끝나면 원래
type을 복원한다. 녹음 세션이나 외부 기능의 나중 변경을 덮어쓰지 않는다. 필기는 기존
idle/fade 뒤 source.onended, 쪽 넘김은 마지막 source 종료, 카페는 완료/stop/dispose,
낭독은 완료/실패/close에서 해제한다. 브라우저의 playback 적용 방식은 iOS/호스트에
달려 있고 다른 미디어를 일시 중지할 수 있다. 네이티브는 mixWithOthers를 명시하지만
웹에 같은 혼합 동작을 보장하지 않는다.

근거: [WebKit의 playback 안내](https://bugs.webkit.org/show_bug.cgi?id=237322),
[Audio Session API 초안](https://www.w3.org/TR/audio-session/),
[Apple playback](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback).


## 공통 화면 복귀 구현 · 2026-11-25

## 첫 종이의 필사 예시 · 2026-11-28

첫 종이에 보여 주는 예시 한 줄은 미리보기에서 그린다. 첫 필사를 고르면
`Workspace`의 메모리에서 현재 초안과 같은 쪽 ID에 원문을 붙이고 기존 편집기로
입력한다. 실제 입력부터 기존 초안 저장 경로를 호출해 사용자가 쓴 본문과 안내에
쓰는 원문을 함께 보존한다. 입력 전에는 저장용 라이브러리와 첫 입력의 ID·조합을
바꾸지 않는다. 빈 종이로 전환하면 같은 편집기에서 예시 안내를 접는다.

## 명상 발과 걷는 팔의 자세 · 2026-11-28

명상에서 좌우 발목을 각 무릎 쪽에 놓고 앞뒤로 어긋나게 한다. 맨발은 둥근 발 표면을
하나로 그리고, 발목 높이를 계산할 때 같은 크기와 회전을 쓴다. 걸음의 위상은
발과 반대 방향으로 어깨·손목을 움직인다. 보행 팔 동작은 움직이는 정도를 따라 줄어들고
기존 앉기와 물건 사용 때는 각 자세의 손 위치를 따른다.
