# 필사 카페 · 공간 직접 이용 · 2026-11-22

사용자가 중간 규모의 카페 시안을 선택하고 하단 버튼 대신 공간 안의 대상을 직접
누르는 1인칭 경험을 요청했다. Flutter·Dart와 기존 입력·저장 구조를 유지한다.

- 바닥 클릭: 가까운 실제 바닥의 위치까지 가구를 돌아 걸어간다.
- 드래그: 서 있는 위치에서 시선을 돌린다. 이동 중에는 걸음과 도착 후 동작을 취소한다.
- 책상 클릭: 창가·큰 책상·안쪽 자리로 이동해 앉는다. 앉은 책상·노트를 다시 누르면 쓴다.
- 나의 책장: 지금 펼친 쪽과 내 책을 선택한다. 선택만으로 기록을 만들지 않는다.
- 추천 서가: 추천 도서와 이유를 보고 공식 원문 페이지를 별도 브라우저로 연다.
- 펜과 노트: 기존 쓰기 도구 화면을 열어 독립적인 종이·펜·글꼴을 고른다.
- 일어나기: 현재 의자 옆으로 돌아간다. 출입문: 카페 방문을 끝낸다.

하단 자리 패널·방향 버튼·고정 쓰기 버튼을 제거했다. 작은 이름표는 대상의 3D 위치에
붙고 실제 면 클릭과 같은 동작을 실행한다. 상단 공간 안내는 키보드·스크린리더용
동등한 경로다. WASD·방향키와 동작 줄이기를 지원한다.

## 공간과 렌더

방은 8.8×10m, 천장 2.95m다. 중앙은 장축 3m·폭 1.15m의 6인 테이블이며 창가 책상,
안쪽 자리, 원목 서가, 올리브 벤치, 문구대와 후면 카운터를 한 좌표계에 구성한다.
22cm 충돌 여유와 9cm 이하 간격의 구간 검사를 사용해 A* 경로의 가구 관통을 막는다.
이 수치는 코드의 배치·경로 기준이며 실제 건축물·실기기 이용성 검증 결과가 아니다.

생성 이미지는 배치와 재질 방향의 기준이다. 실행 화면은 실제 Flutter Canvas의
원근 투영 기하·텍스처·단순 조명·깊이 정렬로 표시한다. 사진 같은 시안과 실행 화면을
동일한 결과로 소개하지 않는다. 깊이 버퍼 없는 렌더의 겹침·광원 표현에는 한계가 있다.
비유한 포인터·카메라 값을 거절하고 yaw를 정규화한다. 이 방어 처리를 이전 모바일
빈 화면의 확인된 원인이나 해결 완료로 표시하지 않는다.

## 추천 서가의 출처

책·저자 정보와 원문 연결은 아래 공식 자료를 확인했다. 앱의 추천 이유는 쓰는 인간의
편집 제안이며 자료 제공 기관의 추천을 뜻하지 않는다. 원문 본문·번역·표지 파일을
앱에 새로 복제하지 않았다. 외부 링크 열기는 네트워크와 브라우저 환경에 의존한다.

## 보존과 검증 경계

지금 쓰던 쪽은 기존 입력 컨트롤러·본문·선택·한글 조합을 유지한다. 다른 책은 기존
이어 쓰기 경로를 사용한다. 쓰기 전 저장 큐·계정 상태를 확인하고 실패 시 방을 유지한다.
서가 탐색과 도구 열기만으로 사용자 기록을 만들지 않는다. 쇼핑·다중 접속은 추가하지 않았다.
현재 방문 상태는 저장 스키마에 추가하지 않는다. 배포·실행 결과는 verification.md를 따른다.

네 역할을 점검했다. 디자이너는 공간 안의 조작과 가구 비례를, 기획자는 걷기·착석·
쓰기·중단의 구분을, 마케터는 시안·렌더·게시·실기기 검증의 경계를, 개발자는 광선 판정·
충돌 경로·입력·저장·복원을 확인했다. 새 판단은 브랜드 페르소나 문서에 남겼다.
