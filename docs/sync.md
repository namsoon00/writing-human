# PC·모바일 기록 동기화

현재 제공하는 같은 웹 링크를 PC와 모바일 브라우저에서 같은 ChatGPT 계정으로 열어 사용한다. Flutter 클라이언트를 유지하며, Sites의 기존 비공개 로그인 + Worker + D1을 사용한다. 설치형 iOS·Android 앱은 현재 로컬 저장을 유지한다. 설치형 앱의 별도 계정 인증은 아직 연결하지 않았다. 서비스 접근 토큰을 앱에 넣어 이 제한을 우회하지 않는다.

## 사용자 흐름

1. 실제 책장 URL(예시 ?demo=reference를 제외한 주소)을 두 기기에서 같은 계정으로 연다.
2. 기존 버전의 기록이 있다면 책장 상단의 ‘기기 기록 … 가져오기’를 눌러 계정 책장에 합친다. 기존 익명 로컬 원본은 삭제하거나 덮어쓰지 않는다. 서로 다른 계정에 자동으로 기존 기록을 보내지 않는다.
3. 작성 내용은 기기에 먼저 저장한다. 입력이 잠잠해지면 약 1초 후 동기화를 시도하고, 다른 기기에서는 약 12초 간격 또는 앱 복귀 시 변경을 가져온다. 구름 버튼이나 필사 메뉴에서 ‘지금 동기화’도 사용할 수 있다.
4. ‘저장됨’은 기기 저장이고 ‘기기 간 동기화 완료’는 서버 버전까지 확인한 상태다. 네트워크·로그인·저장 오류는 별도로 표시한다. 최초 앱 로딩에는 네트워크가 필요하며 설치형 오프라인 PWA를 제공한다고 주장하지 않는다.

## 계정과 서버

- `.openai/hosting.json`의 기존 project_id와 owner-private 접근 범위를 유지했다. d1은 DB다. static 호스팅을 Worker + dist/client의 Flutter 정적 자산으로 전환했다.
- 서버는 Sites가 주입하는 oai-authenticated-user-id를 사용자 키로 사용한다. 브라우저 JSON·쿼리의 사용자 ID를 신뢰하지 않는다. 사용자별 sync_libraries 행에 버전과 스냅샷을 저장한다.
- 클라이언트는 API 세션에서 확인한 계정 ID를 X-Writing-Human-Account로 함께 보낸다. 서버는 실제 요청 계정과 다르면 412로 거절한다. 세션 확인 직후 다른 계정으로 바뀌는 경합에서도 이전 기록을 보내지 않는다. 이 헤더는 인증 수단이 아니라 요청 계정 일치 조건이다.
- 변경 API에는 같은 출처 Origin, JSON, 전용 클라이언트 헤더를 요구한다. 요청 크기는 2 MiB까지다. 큰 기록은 로컬에 보존하고 서버 제한을 표시한다. API는 사용자 기록·SQL 오류·토큰을 로그나 오류 응답에 포함하지 않는다.
- localStorage는 계정 ID별 키로 분리하고, 마지막 확인 계정을 보관해 연결이 끊겨도 해당 기기 기록을 유지한다. 계정이 바뀌면 전송을 멈추고 이전 계정의 UI를 숨긴다. 로그인 만료가 확인되면 다시 인증할 때까지 계정 책장을 가린다.
- `/api/sync/health`는 비공개 Sites 게이트 안에서 서비스 점검용으로 스키마 준비 여부와 요청 origin만 반환한다. 개인 기록을 조회하지 않는다. 사용자 데이터 API는 서비스 접근 토큰만으로는 사용할 수 없고 사용자 식별이 필요하다.
- Drizzle의 SQL 및 메타데이터를 소스에 포함했다. 런타임 요청 중 테이블을 만들거나 바꾸지 않는다. Sites가 배포 전에 마이그레이션을 적용한다.

## 충돌과 입력 보존

서버는 버전이 맞을 때만 원자적으로 갱신한다. 오래된 쓰기는 409를 반환한다. 클라이언트는 마지막 동기화 스냅샷, 현재 로컬 기록, 최신 서버 기록을 세 방향으로 비교한다. 다른 페이지의 수정은 합치고, 같은 본문·원문·책 연결을 다르게 고친 경우 다른 버전은 ‘충돌 보관’ 필사로 남긴다. 텍스트를 임의로 이어 붙이지 않는다. 양쪽에서 같은 쪽 번호를 추가해도 ID와 본문을 모두 유지하고 번호를 정리한다.

기록 삭제는 아직 없으며 병합은 append-only다. 삭제 기능을 추가할 때는 삭제 표식과 복구 정책을 먼저 설계해야 한다. 표지 이름 등의 메타데이터 편집도 현재 UI 범위에 없다.

한글 조합 중에는 동기화를 미루고, 포커스가 있는 편집기의 본문·선택 영역을 원격 변경으로 바꾸지 않는다. 원격 변경이 대기 중이면 입력을 마친 뒤 반영한다. 적용이 가능한 시점에만 편집기를 새 키로 복원하며 TextEditingController의 값/composing을 입력 리스너에서 다시 쓰지 않는다. 전송 중 추가한 입력은 응답의 이전 스냅샷으로 되돌리지 않고 다시 병합한다.

마지막 위치의 실제 사용자 변경 여부를 별도 보관한다. 이미 다른 기기에서 이동한 뒤, 사용하지 않는 기기가 오래된 화면 위치를 반복해서 서버로 보내지 않는다. 화면에 남아 있는 위치와 계정의 최신 위치를 구분하고, 새 실행에서는 최신 위치로 복원한다.

SQLite는 버전 3으로 이전하며 기존 본문·선택 영역·스크롤·도구 설정을 유지한다. sync_state에 기준 버전과 마지막 동기화 스냅샷을 함께 보관한다. 동기화로 페이지 번호가 겹칠 때의 재배열도 트랜잭션으로 처리한다.

## 개발과 검증

```sh
flutter pub get
npm ci
npm run db:local
npm run build
npm run dev
```

개발 주소는 http://127.0.0.1:4173 이다. 로컬 미리보기의 로그인은 합성 계정 local-writer를 사용하며, 서버 계정 확인과 실제 Sites SSO를 구분한다. 로컬 로그인 코드는 tool/dev_sync.mjs에만 있고 배포 Worker에는 포함하지 않는다. 프로덕션은 Sites를 통해서만 배포한다. Worker를 인증 게이트 없이 독립 공개 배포하지 않는다.

```sh
flutter analyze
flutter test
npm run test:server
# npm run dev 실행 후 실제 로컬 Worker + D1 HTTP 검사:
node --test server/http.integration.mjs
```

HTTP 통합 검사는 loopback 주소에만 합성 데이터를 쓸 수 있게 제한했다. Flutter 테스트의 두 SQLite 파일, 메모리 원격 저장소, Node의 실제 SQLite, 로컬 Wrangler/D1, 배포 서버 및 실기기는 서로 다른 검증 범위다. 결과는 docs/verification.md에 기록한다.
